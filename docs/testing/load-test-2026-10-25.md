# Local load test (2026-10-25)

This is a baseline for NFR-PERF, MET-2, MET-4, MET-5 and EVAL-2 on a developer laptop. The deployed test (OI-33) is still needed: local numbers exclude network latency and cold starts.

## Set-up

| Item | Detail |
|---|---|
| Server | Production build (`next start`, one process) on the same Mac as the database |
| Database | The isolated E2E database (`thapar_sns_e2e`, PostgreSQL 17.9 in Docker) holding the official faculty directory (577 profiles). The development database was never used. |
| Script | `scripts/load/run.mjs`. No extra dependencies. Each virtual user signs in with the E2E test sign-in and has its own client address. |
| Run | 200 virtual users, a 60-second mixed workload with 1 to 3 seconds of think time, after a registration burst |

**Workload mix**

| Share | Request |
|---|---|
| 35 % | Notifications list |
| 20 % | Interest toggle (write, with outbox) |
| 20 % | Interest count |
| 15 % | Events page (server-rendered) |
| 10 % | Faculty search page |

## Results

| Request | Requests | p50 ms | p95 ms | p99 ms | Errors | Rate-limited |
|---|---|---|---|---|---|---|
| Registration burst: 200 at once, 100 places | 200 | 423 | 623 | 641 | 0 | 0 |
| GET /api/events/{id}/interest | 1200 | 5 | 12 | 209 | 0 | 0 |
| PUT /api/events/{id}/interest | 1275 | 8 | 24 | 288 | 0 | 0 |
| GET /api/notifications | 2055 | 5 | 11 | 346 | 0 | 0 |
| GET /events (page) | 897 | 11 | 29 | 448 | 0 | 0 |
| GET /faculty?q= (page) | 586 | 16 | 30 | 449 | 0 | 0 |

- **Mixed workload:** 6,013 requests in 60 s (about 100 per second), overall p95 22 ms, 0 server errors.
- **Burst correctness:** exactly 100 registered and 100 waitlisted.

**Search latency at the query layer** (`scripts/load/search-latency.ts`, 300 searches each, warm database):

| Search | p50 ms | p95 ms |
|---|---|---|
| Faculty: tsvector plus trigram, 577 profiles | 5.1 | 5.9 |
| Study material: tsvector, 2,000 temporary rows (removed afterwards) | 6.9 | 16.1 |

## Reading the results

| Target | Result |
|---|---|
| MET-2 / NFR-PERF (CRUD p95 < 200 ms) | Met for the mixed workload; every endpoint's p95 was 30 ms or less |
| MET-4 (full-text search < 100 ms) | Met: 6 ms and 16 ms p95 |
| MET-5 / EVAL-2 (200+ concurrent users) | Met: 200 users with no errors and no throttling |

- **Registration burst.** All 200 users register for the same event in the same instant. The row lock that guarantees the capacity rule serialises them, so the last one waits about 0.6 s. That is the price of correctness for a worst-case burst, not normal CRUD latency.
- **p99 spikes of 200 to 450 ms.** They occur in the first seconds, while the burst is still draining and the server is warming up.
